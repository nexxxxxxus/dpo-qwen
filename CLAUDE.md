# dpo-qwen

## Цель проекта

Сгенерировать ответы Qwen через vLLM, разметить пары chosen/rejected и обучить модель через DPO (TRL).

## Схема работы (важно)

- **Mac** — здесь ты работаешь: пишешь и редактируешь код. GPU и vLLM на Mac нет, генерацию и обучение локально не запускай.
- **Сервер** — 8× NVIDIA A100 80GB, Ubuntu 22.04, CUDA 12.8. Доступ: `ssh a100` (хост описан в `~/.ssh/config` пользователя, пользователь `nsibgatullin`, включён `ForwardAgent` для git). Claude Code на сервере не работает, поэтому все команды на сервере выполняй с Mac через `ssh a100 '<команда>'`.
- **Код** переносится только через git: на Mac `commit` + `push`, на сервере `git pull`. Не копируй код через scp.
- **Тяжёлые файлы** (веса, датасеты, результаты) — только на сервере, никогда не в git.

## Пути на сервере

- Код: `~/dpo-qwen`
- `DATA_DIR=~/data/dpo-qwen` (внутри `models`, `data`, `outputs`, `hf_cache`). Это постоянное место: по словам админа, своё хранится в домашней папке, она видна только владельцу. `/data/shared` — общие модели и датасеты только для чтения, их наполняют менторы (папка команды — `/data/shared/dpo_team`); папки `/data/teams` нет и переезда не будет.
- `HF_HOME=~/data/dpo-qwen/hf_cache` (задан в конце `~/.bashrc`, переопределяет админский `$HOME/hf`)
- Окружение: `~/dpo-qwen/.venv` — conda-окружение с Python 3.12 из канала `conda-forge` (у системного Python 3.10 нет `python3-venv`; каналы Anaconda по умолчанию требуют принять условия использования, поэтому не используются). Скрипты запускай через `scripts/run.sh <скрипт>` (обёртка задаёт `LD_LIBRARY_PATH=.venv/lib`; без неё импорт vLLM падает с `CXXABI_1.3.15 not found`), пакеты ставь через `.venv/bin/pip`.
- Модель: `Qwen/Qwen3-8B`, общая копия в `/data/shared/dpo_team/models/Qwen3-8B` (только чтение, положил ментор), путь прописан в `configs/model.yaml`. В `<DATA_DIR>/models` — только свои чекпойнты. В скриптах раскрывай путь через `Path(...).expanduser()`, не вписывай логин. У Qwen3 по умолчанию включён режим размышлений (`<think>`); при генерации отключай его через `chat_template_kwargs={"enable_thinking": False}`.

## Правила безопасности

- Сервер общий, GPU выдаёт только Slurm. Любой запуск на GPU — через `sbatch --gres=gpu:N ...` или `srun --gres=gpu:N ...`; карту выбирает Slurm, `CUDA_VISIBLE_DEVICES` вручную не задавай. Процесс на GPU вне Slurm (например, из tmux) в течение минуты убивает системный скрипт `gpu_guard` — это выглядит как молчаливый SIGKILL движка vLLM. Задачу, чья карта около двух часов загружена меньше чем на 5%, отменяет `gpu_reaper`. Без `-t` задача живёт 8 часов, максимум — 2 суток.
- Никогда не завершай чужие процессы, не удаляй файлы вне `~/dpo-qwen` и выбранной папки данных, не выполняй `sudo`. Если шаг требует sudo — остановись и скажи пользователю.
- Перед скачиванием модели спроси пользователя, какую модель брать.
- Запуски на GPU отправляй через `sbatch` (он переживает обрыв SSH): `sbatch --gres=gpu:1 --cpus-per-task=8 --mem=64G -t <время> -J nadir-<задача> -o <лог> --wrap "cd ~/dpo-qwen && scripts/run.sh <скрипт>"`. Состояние — `squeue -u nsibgatullin`.
- Долгие команды без GPU (скачивание, установка) запускай в tmux (`tmux new -d -s nadir-<задача> '<команда>'`), чтобы обрыв SSH их не убил. Соединение с сервером иногда рвётся — при `Connection reset` просто повтори команду.
- Не пушь в `main` то, что не проверено.

## Зависимости

`requirements.txt` закрепляет vLLM, PyTorch, torchcodec и flashinfer-jit-cache в сборке `+cu129`: драйвер сервера (570.x) поддерживает только CUDA 12.x, а сборки по умолчанию из PyPI рассчитаны на CUDA 13. При обновлении vLLM обновляй все эти строки и адреса индексов вместе.

## Раскладка по GPU (A100 80GB)

До 14B — 1 карта на копию модели; 32B — `tensor_parallel_size=2`; 72B — `tensor_parallel_size=4`.
