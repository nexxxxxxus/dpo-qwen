# dpo-qwen

Инструкции для Codex. Те же правила для Claude Code лежат в `CLAUDE.md`; при изменении одного файла обновляй и второй.

## Цель проекта

Сгенерировать ответы Qwen через vLLM, разметить пары chosen/rejected и обучить модель через DPO (TRL).

## Схема работы (важно)

- **Локальная машина пользователя** — здесь пишется и редактируется код. GPU и vLLM на ней нет, генерацию и обучение локально не запускай.
- **Сервер** — 8× NVIDIA A100 80GB, Ubuntu 22.04, драйвер поддерживает CUDA до 12.8. Вход по SSH-ключу пользователя. Имя хоста и логин у каждого свои: посмотри в `~/.ssh/config` пользователя, а если подходящей записи нет — спроси. Ниже хост обозначен как `<сервер>`, логин — как `<логин>`.
- Если ты запущен на локальной машине, команды на сервере выполняй через `ssh <сервер> '<команда>'`. Если ты запущен на самом сервере, выполняй их напрямую, но правила про Slurm ниже действуют так же.
- **Код** переносится только через git: локально `commit` + `push`, на сервере `git pull`. Не копируй код через scp.
- **Тяжёлые файлы** (веса, датасеты, результаты) — только на сервере, никогда не в git.

## Пути на сервере

- Код: `~/dpo-qwen`
- `DATA_DIR=~/data/dpo-qwen` (внутри `models`, `data`, `outputs`, `hf_cache`). Домашняя папка видна только владельцу, поэтому у каждого участника своя копия данных и модели. `/data/shared` — общие модели и датасеты только для чтения, их наполняют менторы; сам туда ничего не пиши.
- `HF_HOME=~/data/dpo-qwen/hf_cache`. Задаётся в конце `~/.bashrc` строкой `export HF_HOME=$HOME/data/dpo-qwen/hf_cache`; она переопределяет админскую `$HOME/hf`, которую править не нужно.
- Окружение: `~/dpo-qwen/.venv` — conda-окружение с Python 3.12 из канала `conda-forge` (у системного Python 3.10 нет `python3-venv`; каналы Anaconda по умолчанию требуют принять условия использования, поэтому не используются). Команды создания — в `README.md`, раздел «Окружение на сервере».
- Скрипты запускай через `scripts/run.sh <скрипт>`: обёртка задаёт `LD_LIBRARY_PATH=.venv/lib`, без неё импорт vLLM падает с `CXXABI_1.3.15 not found`. Пакеты ставь через `.venv/bin/pip`.
- Модель: `Qwen/Qwen3-8B` в `<DATA_DIR>/models/Qwen3-8B`. Путь прописан в `configs/model.yaml` через `~`; в скриптах раскрывай его через `Path(...).expanduser()`, не вписывай логин.
- У Qwen3 по умолчанию включён режим размышлений (`<think>`); при генерации отключай его через `chat_template_kwargs={"enable_thinking": False}`.

## Первый запуск у нового участника

Проверь на сервере, что уже есть, и доделай недостающее по порядку:

1. Репозиторий склонирован в `~/dpo-qwen`.
2. Созданы папки `~/data/dpo-qwen/{models,data,outputs,hf_cache}`.
3. В конце `~/.bashrc` есть строки `umask 002` и `export HF_HOME=...` (см. выше).
4. Окружение `.venv` создано и пакеты поставлены из `requirements.lock.txt`.
5. Модель лежит в `~/data/dpo-qwen/models/Qwen3-8B` (16 ГБ). Если её нет — сначала проверь `/data/shared`, затем спроси пользователя, прежде чем скачивать.
6. Тест `scripts/smoke_test.py` через `sbatch` завершается двумя ответами без ошибок.

## Правила безопасности

- Сервер общий, GPU выдаёт только Slurm. Любой запуск на GPU — через `sbatch --gres=gpu:N ...` или `srun --gres=gpu:N ...`; карту выбирает Slurm, `CUDA_VISIBLE_DEVICES` вручную не задавай.
- Процесс на GPU вне Slurm (например, из tmux) в течение минуты убивает системный скрипт `gpu_guard` — это выглядит как молчаливый SIGKILL движка vLLM.
- Задачу, чья карта около двух часов загружена меньше чем на 5%, отменяет `gpu_reaper`. Без `-t` задача живёт 8 часов, максимум — 2 суток.
- Никогда не завершай чужие процессы и задачи, не удаляй файлы вне `~/dpo-qwen` и `~/data/dpo-qwen`, не выполняй `sudo`. Если шаг требует sudo — остановись и скажи пользователю.
- Перед скачиванием модели спроси пользователя, какую модель брать.
- Запуски на GPU отправляй через `sbatch` (он переживает обрыв SSH):

  ```bash
  sbatch --gres=gpu:1 --cpus-per-task=8 --mem=64G -t <время> \
    -J <имя>-<задача> -o ~/data/dpo-qwen/outputs/<дата>-<имя>-<что>/log.txt \
    --wrap "cd ~/dpo-qwen && scripts/run.sh <скрипт>"
  ```

  Папку для лога создай заранее. Состояние — `squeue -u <логин>`, отмена своей задачи — `scancel <номер>`.
- Долгие команды без GPU (скачивание, установка) запускай в tmux (`tmux new -d -s <имя>-<задача> '<команда>'`), чтобы обрыв SSH их не убил. Соединение с сервером иногда рвётся — при `Connection reset` просто повтори команду.
- Каждый работает в своей ветке и вливает её в `main` через Pull Request. Не пушь в `main` то, что не проверено на сервере.

## Зависимости

`requirements.txt` закрепляет vLLM, PyTorch, torchcodec и flashinfer-jit-cache в сборке `+cu129`: драйвер сервера (570.x) поддерживает только CUDA 12.x, а сборки по умолчанию из PyPI рассчитаны на CUDA 13. При обновлении vLLM обновляй все эти строки и адреса индексов вместе.

## Раскладка по GPU (A100 80GB)

До 14B — 1 карта на копию модели; 32B — `tensor_parallel_size=2`; 72B — `tensor_parallel_size=4`.
