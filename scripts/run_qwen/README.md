# run_qwen: Qwen3-8B как HTTP-сервер (SGLang)

`serve.sh` поднимает SGLang с моделью `/data/shared/dpo_team/models/Qwen3-8B` и API, совместимым с OpenAI. После запуска к модели можно обращаться через `curl` с самого сервера.

Скрипт повторяет запуск из гайда ментора (`/data/shared/dpo_team/scripts/sglang_qwen3/README.md`) и использует его готовое окружение. Отличия: все пути абсолютные, лог пишется в вашу папку, сервер слушает только `127.0.0.1`.

## Запуск

```bash
sbatch serve.sh
```

Задача берёт одну карту через Slurm. Лог пишется в `qwen-serve_<номер задачи>.log` в папке, из которой вызван `sbatch`. Сервер готов, когда отвечает проверка:

```bash
curl http://127.0.0.1:30000/health && echo OK
```

Остановить: `scancel <номер задачи>` (номер показывает `squeue -u $USER`).

## Запрос

```bash
curl http://127.0.0.1:30000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3-8B",
    "messages": [{"role": "user", "content": "Сколько будет 2+2?"}],
    "max_tokens": 100,
    "chat_template_kwargs": {"enable_thinking": false}
  }'
```

Ответ лежит в `choices[0].message.content`. Несколько вариантов ответа на один запрос дают параметры `"n": 2, "temperature": 0.8`.

У Qwen3 по умолчанию включён режим размышлений. Поле `"chat_template_kwargs": {"enable_thinking": false}` его выключает. Без этого поля модель сначала рассуждает, и `max_tokens` тратится в том числе на рассуждения.

## Проверка одной командой

`smoke.sh` в одной задаче Slurm поднимает сервер, задаёт модели вопрос через `scripts/smoke_test.py` и останавливает сервер:

```bash
sbatch --gres=gpu:1 --cpus-per-task=8 --mem=64G -t 0:20:00 -J <имя>-smoke \
  -o ~/data/dpo-qwen/outputs/<папка запуска>/log.txt \
  --wrap "cd ~/dpo-qwen && scripts/run_qwen/smoke.sh"
```

В конце лога должны быть два ответа и строка `SMOKE TEST PASSED`. Проверка использует порт `30011`, чтобы не мешать уже работающему серверу.

## Что нужно знать

- **Адрес.** Сервер слушает только `127.0.0.1:30000`, то есть доступен всем пользователям этого сервера, но не снаружи. С ноутбука — через проброс порта: `ssh -L 30000:localhost:30000 <логин>@<сервер>`, затем те же `curl` у себя.
- **Порт занят.** Если сервер уже кем-то запущен на этом порту, второй не стартует — можно просто пользоваться работающим. Свой на другом порту: `sbatch --export=ALL,PORT=30001 serve.sh`.
- **Время жизни.** По умолчанию 8 часов, максимум 2 суток: `sbatch -t 2-00:00:00 serve.sh`. Задачу, у которой карта около двух часов загружена меньше чем на 5%, система отменяет сама, поэтому простаивающий сервер проживёт около двух часов.
- **Окружение.** Скрипт берёт Python и SGLang из окружения ментора `/home/gpkiryukhov/.conda/envs/sglang`, а драйвер совместимости CUDA 13 — из `/home/gpkiryukhov/cuda-compat-13-0/compat`. Другие пути: `sbatch --export=ALL,SGLANG_ENV=/путь/к/env,COMPAT_DIR=/путь/к/compat serve.sh`.
- **Другая модель.** `sbatch --export=ALL,MODEL=/путь/к/модели serve.sh`; имя в запросах при этом остаётся `Qwen3-8B`.
