# run_qwen: Qwen3-8B как HTTP-сервер

`serve.sh` поднимает vLLM с моделью `/data/shared/dpo_team/models/Qwen3-8B` и API, совместимым с OpenAI. После запуска к модели можно обращаться через `curl` с самого сервера.

## Запуск

```bash
sbatch serve.sh
```

Задача берёт одну карту через Slurm. Лог пишется в `qwen-serve_<номер задачи>.log` в папке, из которой вызван `sbatch`. Модель загружается около минуты; сервер готов, когда отвечает проверка:

```bash
curl http://127.0.0.1:8011/health && echo OK
```

Остановить: `scancel <номер задачи>` (номер показывает `squeue -u $USER`).

## Запрос

```bash
curl http://127.0.0.1:8011/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "Qwen3-8B",
    "messages": [{"role": "user", "content": "Сколько будет 2+2?"}],
    "max_tokens": 100
  }'
```

Ответ лежит в `choices[0].message.content`. Несколько вариантов ответа на один запрос дают параметры `"n": 2, "temperature": 0.8`.

Режим размышлений Qwen3 (`<think>`) на сервере выключен. Включить для одного запроса: добавить в тело `"chat_template_kwargs": {"enable_thinking": true}`.

## Что нужно знать

- **Адрес.** Сервер слушает только `127.0.0.1:8011`, то есть доступен всем пользователям этого сервера, но не снаружи. С ноутбука — через проброс порта: `ssh -L 8011:localhost:8011 <логин>@<сервер>`, затем те же `curl` у себя.
- **Порт занят.** Если сервер уже кем-то запущен, второй на том же порту не стартует. Другой порт: `sbatch --export=ALL,PORT=8012 serve.sh`.
- **Время жизни.** По умолчанию 8 часов, максимум 2 суток: `sbatch -t 2-00:00:00 serve.sh`. Задачу, у которой карта около двух часов загружена меньше чем на 5%, система отменяет сама, поэтому простаивающий сервер проживёт около двух часов.
- **Окружение.** Скрипт берёт Python и vLLM из `/home/nsibgatullin/dpo-qwen/.venv`. Своё окружение: `sbatch --export=ALL,VENV=/путь/к/.venv serve.sh`.
- **Другая модель.** `sbatch --export=ALL,MODEL=/путь/к/модели serve.sh`; имя в запросах при этом остаётся `Qwen3-8B`.
