# Проверка моделей на бенчмарках

Набор проверяет, не потеряла ли Qwen3-8B общие способности после дообучения. Десять моделей — базовая и девять LoRA-адаптеров из перебора гиперпараметров (lr 1e-5, 2e-5, 5e-5 × beta 0.05, 0.1, 0.3) — отвечают на вопросы пяти бенчмарков, ответы оцениваются автоматически, итог — одна таблица.

Адаптеры учили модель выделять жирным главное в коротком ответе. Нас интересует разница между базовой моделью и каждым адаптером при одинаковой проверке, а не абсолютные цифры.

## Что внутри

| Файл | Назначение |
|---|---|
| `run_bench.sh` | поднимает vLLM с базовой моделью и адаптерами, запускает проверку, останавливает сервер |
| `run_bench.py` | задаёт вопросы, сохраняет ответы, считает оценки и таблицу |
| `setup_bench.sh` | доставляет в окружение пакеты для оценки |
| `download.py` | скачивает бенчмарки с Hugging Face (уже скачаны, лежат в `data/benchmarks/`) |
| `third_party/` | проверяющие правила IFEval и Multi-IF из официальных репозиториев |
| `data/benchmarks/` | вопросы, 8348 штук, 6 МБ |

## Бенчмарки

| Бенчмарк | Что проверяет | Язык | Вопросов | Главная цифра в таблице |
|---|---|---|---|---|
| IFEval | следование инструкциям («не меньше 300 слов», «без запятых») | английский | 541 | доля ответов, где выполнены все инструкции (строго) |
| Multi-IF | то же в диалоге из трёх ходов, инструкции накапливаются | русский | 515 диалогов | среднее по трём ходам от четырёх точностей хода, как в коде Multi-IF |
| MMLU-Redux 2.0 | общие знания, выбор из четырёх вариантов, 57 предметов | английский | 5700 | точность на 5330 вопросах без ошибок разметки |
| INCLUDE | региональные знания из экзаменов, выбор из четырёх | русский | 552 | точность |
| PolyMath | математика, ответ в `\boxed{}`, четыре уровня | английский и русский | по 500 | взвешенная точность: уровни весят 1 : 2 : 4 : 8 |

Все запросы идут без системного промпта, с выключенными размышлениями (`enable_thinking: false`) и температурой 0 — так же, как обучались адаптеры. Режим с размышлениями не поддержан.

## Что нужно

- Окружение с vLLM — то же, в котором шла проверка адаптеров (`.venv` из `scripts/train_dpo/setup_env.sh`).
- Базовая модель Qwen3-8B и папки адаптеров (`.../epoch_0/adapter_model.safetensors`).
- Одна карта с памятью от 24 ГБ. Доступ в интернет нужен только для шага 2.

## Запуск

### 1. Распаковать

```bash
tar -xzf qwen_bench.tar.gz
cd qwen_bench
```

Куда угодно: скрипты ищут вопросы и пишут результаты рядом с собой.

### 2. Доставить пакеты для оценки (один раз)

```bash
VENV=/путь/к/.venv ./setup_bench.sh
```

Ставит `nltk`, `langdetect`, `immutabledict`, `absl-py`, `emoji` и скачивает данные токенизатора NLTK в `nltk_data/`. PyTorch и vLLM не затрагиваются; скрипт это проверяет и останавливается, если их версии изменились.

### 3. Пробный прогон

Сначала по 20 вопросов на бенчмарк, чтобы убедиться, что сервер поднимается и адаптеры находятся:

```bash
export VENV=/путь/к/.venv
export MODEL=/путь/к/Qwen3-8B
export RUNS=/workspace-SR006.nfs2/gpkiryukhov/dpo/data/dpo-qwen/outputs
RESULTS=$PWD/results_trial ./run_bench.sh --limit 20
```

В начале скрипт печатает список моделей. Адаптеры он находит сам: все папки `RUNS/*tune-lr<lr>-beta<beta>/epoch_0`. Если список неполный или папки называются иначе, задайте его явно:

```bash
export ADAPTERS="lr2e-5-beta0.1=/путь/к/запуску/epoch_0 lr5e-5-beta0.3=/путь/к/другому/epoch_0"
```

### 4. Полный прогон

```bash
tmux new -s bench
./run_bench.sh 2>&1 | tee bench.log        # без Slurm; карта — через CUDA_VISIBLE_DEVICES
# или со Slurm, из этой же папки:
sbatch -o bench.log run_bench.sh
```

Модели идут по очереди: сначала базовая, потом адаптеры. По оценке (не замеру) это 15–20 минут на модель на A100, около трёх часов на десять.

Прогон можно прервать и запустить заново той же командой: сохранённые ответы повторно не запрашиваются. Отдельные модели или бенчмарки:

```bash
BASE=0 ADAPTERS="lr5e-5-beta0.3=/путь/epoch_0" ./run_bench.sh     # один адаптер, без базовой
./run_bench.sh --only ifeval multi_if                               # часть бенчмарков
```

### 5. Таблица

Печатается в конце прогона и сохраняется в `results/bench_table.csv`. Пересчитать по сохранённым ответам, без карты:

```bash
LD_LIBRARY_PATH=$VENV/lib NLTK_DATA=$PWD/nltk_data $VENV/bin/python run_bench.py --score-only
```

Звёздочка у цифры значит, что ответы есть не на все вопросы бенчмарка.

## Какие модели где

На этой машине обучены семь адаптеров; два оставшихся (lr 1e-5 с beta 0.05 и 0.1) обучены на нашем сервере. Варианта два: переслать сюда их папки `epoch_0` (по 87 МБ) и добавить через `ADAPTERS`, либо прогнать их у нас. Результаты с двух машин объединяются простым копированием папок `results/<модель>/` в одно место и пересчётом таблицы (шаг 5). Базовую модель достаточно прогнать на одной машине.

## Что прислать обратно

Папку `results/` целиком: в ней по папке на модель с ответами (`<бенчмарк>.jsonl`) и оценками (`scores.json`), общая `bench_table.csv` и лог сервера `vllm_<порт>.log`.

## Как считаются оценки

- **IFEval и Multi-IF** — правилами из официального кода (`third_party/`). «Строго» — правило проверяется на ответе как есть; «мягко» — ещё и на ответе без первой или последней строки и без звёздочек. Для Multi-IF цифра хода — среднее четырёх точностей: строгой и мягкой, по диалогам и по отдельным инструкциям.
- **MMLU-Redux и INCLUDE** — модель просят закончить ответ строкой «Answer: X» («Ответ: X»), лимит 1024 токена. Берётся буква из последней такой строки; если её нет — отдельно стоящая буква A–D (кириллические А, В, С засчитываются). Ответ, оборванный по лимиту до строки с ответом, считается неверным. В `scores.json` есть `unparsed` — сколько ответов без буквы. Просить «только букву» и давать 16 токенов нельзя: модель в 15–25% случаев всё равно начинает рассуждать, ответ обрывается, и оценка измеряет послушание формату, а не знания.
- **PolyMath** — из ответа берётся содержимое последнего `\boxed{}` и сравнивается с эталоном: как текст после чистки LaTeX либо как число.

## Ограничения

- **Цифры не совпадут с отчётом Qwen.** Там свои формулировки запросов и свой разбор ответов. Ориентиры из отчёта для Qwen3-8B без размышлений: IFEval 83.0, Multi-IF (русский) 59.3, MMLU-Redux 79.5, INCLUDE (русский) 58.9, PolyMath (русский) 22.8.
- **Сравнение ответов PolyMath проще официального.** Ответы, равные эталону только после алгебраических преобразований, а также множества, интервалы и неравенства в другой записи засчитываются как неверные. Цифра занижена для всех моделей одинаково. Код из репозитория PolyMath не взят: у него не указана лицензия.
- **Запросы для MMLU-Redux и INCLUDE без примеров** (zero-shot), формулировка наша; модели разрешено рассуждать перед ответом.
- **Проверено на настоящих моделях** на нашем сервере: IFEval у базовой модели — 82,4 при 83,0 в отчёте Qwen.
- **Один прогон на модель.** При температуре 0 ответы почти воспроизводимы, но разница в несколько десятых процента между моделями — в пределах шума.
