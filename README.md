# dpo-qwen

Дообучение Qwen методом DPO: генерируем ответы модели через vLLM, размечаем пары chosen/rejected и обучаем модель через DPO (библиотека TRL).

## Схема работы

```
Mac (код)  →  git push  →  GitHub  →  git pull  →  сервер (GPU, данные, запуски)
```

- **Код** пишем на своих машинах и переносим на сервер только через git. Через scp код не копируем.
- **Сервер** — 8× NVIDIA A100 80GB, Ubuntu 22.04. Код лежит в `~/dpo-qwen`.
- **Тяжёлые файлы** (веса, датасеты, результаты) живут только на сервере в `DATA_DIR` и никогда не попадают в git.

`DATA_DIR` сейчас — `/home/nsibgatullin/data/dpo-qwen`. Это временное место: когда появится общая папка `/data/dpo-qwen`, данные переедут туда.

```
DATA_DIR/
├── models/     веса моделей
├── data/       датасеты
├── outputs/    результаты запусков
└── hf_cache/   кэш Hugging Face (HF_HOME)
```

## Окружение на сервере

У системного Python на сервере нет модуля `venv`, поэтому окружение создаётся через conda (Python 3.12) в папке `.venv` внутри репозитория:

```bash
cd ~/dpo-qwen
/opt/conda/bin/conda create -y -p .venv python=3.12
.venv/bin/pip install -U pip
.venv/bin/pip install -r requirements.lock.txt
```

`requirements.txt` — список зависимостей, `requirements.lock.txt` — точные версии, с которыми всё проверено.

В `~/.bashrc` на сервере должны быть строки:

```bash
umask 002
export HF_HOME=<DATA_DIR>/hf_cache
```

## Структура репозитория

- `configs/` — конфиги; `configs/model.yaml` хранит путь к модели на сервере
- `scripts/` — запускаемые скрипты
- `src/` — код проекта

## Правила для команды

- **Ветки.** Каждый работает в своей ветке и вливает её в `main` через Pull Request. В `main` попадает только проверенное.
- **GPU.** Сервер общий. Перед запуском смотрим `nvidia-smi` и берём только свободные карты через `CUDA_VISIBLE_DEVICES`. Чужие процессы не завершаем.
- **tmux.** Долгие команды запускаем в tmux, сессии называем `<имя>-<задача>`, например `nadir-generate`.
- **Результаты.** Каждый запуск пишет в `<DATA_DIR>/outputs/<дата>-<имя>-<что>/`, например `2026-10-04-nadir-generate/`, и кладёт туда копию конфига, с которым запускался.

## Раскладка моделей по картам

На A100 80GB: до 14B — одна карта на копию модели; 32B — `tensor_parallel_size=2`; 72B — `tensor_parallel_size=4`.
